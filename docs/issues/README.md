# 問題與變更紀錄

每發現一個缺陷、或新增一項功能，就建立一份紀錄，用於後續追蹤、會議報告與交接。

## 怎麼用

```bash
cp docs/issues/_template.md "docs/issues/$(date +%Y-%m-%d)-簡短標題.md"
```

填寫後把該筆加入下方索引。狀態隨進度更新（調查中 → 待決策 → 實作中 → 已驗證結案）。

## 格式說明

以 8D 手法為骨架但予以精簡（省略跨部門團隊、表揚等行政流程），保留七段：

| 段落 | 用途 |
|---|---|
| 1. 現象 | 使用者實際看到什麼，附具體例子 |
| 2. 影響 | 誰受影響、多嚴重，盡量量化 |
| 3. 調查過程 | **逐項排除**的假設與驗證方式 |
| 4. 根本原因 | 真正的原因與機制 |
| 5. 對策評估 | 各方案比較與採用理由 |
| 6. 驗證 | 改善前後的數據對照 |
| 7. 預防與學習 | 可推廣的通則、流程改善、個人收穫 |

**第 3 段是關鍵。** 說明「排除了哪些可能」比直接給結論更有說服力，也能證明結論來自驗證而非猜測。

功能開發（非缺陷）可省略第 3 段，並將第 1、2 段改寫為「需求緣由」與「預期效益」。
